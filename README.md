# rules — このツリーの書き方

書くときはこれに従う。読むときは `docs/bin/doc`(引数なしで索引、`--help` で全コマンド)。
道具の背景・人間向けの詳細・規約の理由は `ForHuman`。

## どこに書くか {#record}

同じ内容を2箇所に書かない。片方はリンクにする。

| 書くもの | 行き先 |
|---|---|
| 日付が付くもの(いつ何を変えたか、その日の動作確認) | `CHANGELOG.md` |
| 現在形で書けるもの | `<topic>.md` |
| なぜそうしたか・何を採らなかったか | `<topic>.md` の `## 設計判断の記録` |

- CHANGELOG の各エントリ `## YYYY-MM-DD — ...` には `{#id}` を必ず付ける。
- 動作確認は CHANGELOG。例外は恒久的な性質の発見(例: このコンテナに procps が無い)で、
  それはその topic の文書に残す。

## トピックの形 {#newtool}

トップレベルに `<topic>.md` を1枚作るだけ。**索引は生成物なので触らない。**

```markdown
# <topic> — <一行の説明>

**いつ読むか**: <発火条件を / 区切りで>

## 構成
## 構成ファイル一覧
## 運用
## 既知の制限
## 設計判断の記録
```

- 標準節名は `使い方 構成 構成ファイル一覧 セキュリティ上の要点 運用 既知の制限
  設計判断の記録`(id は `usage arch files security ops limits design`)。省略可、
  並べ替え不可、`設計判断の記録` は常に最後。
- 標準名以外の H2 は見出し末尾に `{#id}` を付ける。
- `設計判断の記録` 以外は現在形で書く。他の節に日付の追記が現れたら CHANGELOG へ移す。
- `いつ読むか` は読み手の状況(発火条件)で書く。トピック名の言い換えは不可。
  **1文書に必ず1行**。索引の行そのものなので、無い文書は誰にも見つからない
  (`doc check` が検出)。分割した子文書にも各々必要。

## 分割と入れ子 {#nesting}

**1トピック1ファイルで始める。** フォルダを作るのは文書が2つ以上になったときだけ。
そのとき概要は `<topic>/README.md`、追加分は `<topic>/<name>.md` に置く。

```
billing.md               文書が1つのうちはこれだけ
                         ↓ 2つ目ができたら
billing/README.md        概要(元の billing.md)
billing/design.md        id は billing-design
```

- **id はパスの `/` を `-` に置換したもの。** `billing/design.md` → `billing-design`。
  `<topic>/README.md` はそのフォルダを所有するので id は `<topic>` のまま。
- **フォルダに入れても id は変わらない。** `x-y.md` と `x/y.md` はどちらも id `x-y`。
  だから同じ接頭辞のトピックが増えたら、参照を壊さずいつでもフォルダにまとめられる
  (`x-a.md` と `x-b.md` → `x/README.md` + `x/a.md` + `x/b.md`)。
- **その裏返しで、`x-y.md` と `x/y.md` は同時に置けない**(同じ id になる)。
  新しいフォルダ `x/` を作る前に `doc | grep '^x-'` を確認する。`doc check` も検出する。
- 階層は id ではなくパスから決まる。id からパスは逆算できないので、ファイルの場所は
  `doc toc <topic>` の1行目で確認する。
- **独立した `いつ読むか` が書けないなら分割しない。** 索引に出せず、親を読まないと
  辿り着けない文書になる。
- `設計判断の記録` が150行を超えたら `<topic>/design.md` に分離し、
  `<topic>/README.md` にスタブを残す。
- **「詳細は `<topic>-<name>` を参照」を本文に書かない。** `doc show` / `doc toc` が
  子文書を自動で一覧する。
- 概要の要らないフォルダは `README.md` 無しでよい。中の文書は親の位置に出る。
- 深さ制限なし。ただし `CHANGELOG.md` だけは `CHANGELOG/` の外から概要を持つ
  (`doc` がこのファイルの存在でツリーのルートを判定するため動かせない)。

## 参照 {#style}

- 相互参照は `topic#節ID`。行番号は使わない(編集でずれる)。
  **id にスラッシュは使わない**(パスではなく id を書く)。
- 解決してはいけない参照を例として書くときは、トピック名とアンカーを別トークンに割る
  (`` topic `foo` の `#usage` 節 ``)。1トークンで書くと `doc check` が壊れた参照として報告する。
- このリポジトリの外(利用側プロジェクトそのものの作り)は説明しない。
  「ここではこう使う・こう困る」だけ書く。

## 書いたら {#verify}

`docs/bin/doc check` を通す。
